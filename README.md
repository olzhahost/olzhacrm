# CRM «ОЛЖАПРОЕКТ»

Внутренняя CRM-система для проектной компании: учёт объектов проектирования
и их стадий, журнал писем, договоры, приказы, коммерческие предложения,
табель учёта рабочего времени, авторизация сотрудников с разграничением
прав доступа по ролям.

**Стек:** Next.js 14 (App Router) + Supabase (Postgres + Auth + Storage + RLS).
Хостинг фронтенда — Vercel (бесплатный тариф достаточен для старта).

---

## 2. Логика ролей (кто что видит и может редактировать)

| Роль | Код | Права |
|---|---|---|
| Директор | `director` | Полный доступ ко всему |
| ГИП | `gip` | Свои объекты (где назначен ГИПом) — полный доступ; создаёт КП |
| Инженер | `engineer` | Видит объекты, где числится в команде |
| Бухгалтер | `accountant` | Договоры, КП, финансовая часть |
| Офис-менеджер | `office_manager` | Журнал писем, приказы |
| Кадры (HR) | `hr` | Сотрудники, табель, приказы |
| Наблюдатель | `viewer` | Только просмотр |

Разграничение реализовано **на двух уровнях**:
1. **База данных (RLS)** — `supabase/migrations/0002_rls.sql`. Это основная
   защита: даже если кто-то обойдёт интерфейс и обратится к API напрямую,
   Postgres не отдаст и не позволит изменить данные, на которые нет прав.
2. **Интерфейс** — `lib/auth.ts` (`can(...)`) скрывает кнопки и пункты меню,
   которые всё равно заблокированы на уровне БД. Это только для удобства.

## 3. Разворачивание — пошагово

### Шаг 1. Создать проект в Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) (есть бесплатный тариф).
2. Создайте новый проект (New Project), задайте пароль базы данных — сохраните его.
3. Дождитесь инициализации проекта (1–2 минуты).

### Шаг 2. Применить схему базы данных

1. В панели Supabase откройте **SQL Editor**.
2. Скопируйте содержимое файла `supabase/migrations/0001_init.sql`, вставьте
   и нажмите **Run**.
3. Затем то же самое с `supabase/migrations/0002_rls.sql`.
4. Проверьте: в разделе **Table Editor** должны появиться таблицы
   `employees`, `objects`, `stages`, `letters`, `contracts`, `orders`,
   `commercial_proposals`, `timesheets` и другие.

### Шаг 3. Получить ключи API

В Supabase: **Project Settings → API**. Скопируйте:
- `Project URL`
- `anon public` ключ

### Шаг 4. Настроить проект локально

```bash
# распакуйте/склонируйте проект, затем:
npm install
cp .env.local.example .env.local
```

Откройте `.env.local` и вставьте значения из Шага 3:

```
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...
```

Запустите локально для проверки:

```bash
npm run dev
```

Откройте http://localhost:3000 — должна открыться страница входа.

### Шаг 5. Создать первого пользователя (директора)

1. В Supabase: **Authentication → Users → Add user** (создать вручную,
   указав email и пароль; либо включить регистрацию по приглашению).
2. После создания пользователя откройте **Table Editor → employees** —
   там автоматически появится запись (триггер `on_auth_user_created`)
   с ролью `viewer` по умолчанию.
3. Отредактируйте эту запись прямо в Table Editor: смените `role` на
   `director` и укажите `full_name`. Это будет ваш первый администратор.
4. Все остальные сотрудники создаются так же (через Authentication → Users),
   а затем директор/HR назначает им роль на странице **Сотрудники** в самом
   приложении (без захода в Supabase).

### Шаг 6. Развернуть на Vercel

1. Зарегистрируйтесь на [vercel.com](https://vercel.com) (можно через GitHub).
2. Загрузите проект в свой репозиторий на GitHub (или GitLab/Bitbucket).
3. В Vercel: **Add New → Project**, выберите репозиторий.
4. В настройках окружения (**Environment Variables**) добавьте те же
   переменные, что и в `.env.local`:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
5. Нажмите **Deploy**. Через 1–2 минуты сайт будет доступен по адресу вида
   `olzhaproject-crm.vercel.app`.
6. (Опционально) В **Project Settings → Domains** подключите свой домен,
   например `crm.olzhaproject.kz`.

### Шаг 7. Хранилище файлов (сканы писем, договоров, приказов)

Поля `file_url` в таблицах `letters`, `contracts`, `orders`,
`commercial_proposals` рассчитаны на ссылки из **Supabase Storage**:

1. В Supabase: **Storage → Create bucket**, например `documents`.
2. Настройте политику доступа (Policy) на бакет аналогично RLS-логике
   (кто может загружать/читать файлы).
3. Загрузку файлов из интерфейса CRM можно добавить отдельным шагом —
   базовая структура (поле `file_url`) уже готова в БД, это лишь вопрос
   добавления `<input type="file">` и вызова `supabase.storage.from(...).upload(...)`
   на нужных формах (letters/new, contracts/new и т.д.).

- ✅ Авторизация сотрудников (email + пароль через Supabase Auth)

## 5. Что имеет смысл добавить дальше (по приоритету)

1. **Загрузка файлов** в Supabase Storage для писем/договоров/приказов/КП
   (сканы, PDF) — поля в БД уже готовы.
2. **Отдельная страница «Заказчики»** (сейчас клиенты используются как
   справочник внутри форм; полноценный CRUD ускорит работу).
3. **Уведомления** (например, через Supabase Edge Functions + email/Telegram)
   о приближении сроков сдачи объектов, окончании договоров.
4. **Более гибкие права** — если понадобится доступ "по отделам", а не
   только "по команде объекта".
5. **Экспорт в Excel** реестров (письма, договоры, приказы) — по аналогии
   с уже реализованным экспортом КП в PDF.

## 6. Важно про безопасность

- Никогда не публикуйте `service_role` ключ Supabase (он не используется
  в этом проекте нигде на фронтенде — только `anon` ключ, это осознанно:
  вся защита данных идёт через RLS-политики).
- Пароль от базы данных Supabase храните отдельно, не в репозитории.
- Файл `.env.local` не должен попадать в git (уже добавлен в `.gitignore`).
